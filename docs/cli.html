IsraRecover משורת הפקודה (CLI)

IsraRecover.exe cli <command> [options] מריץ את הבדיקה, הסריקה, השחזור ורופא הקבצים של התוכנה בלי חלון. הוא נבנה כדי שסקריפט או סוכן AI יוכלו להפעיל את התוכנה, לקרוא את הפלט ולהבין למה משהו נכשל: הפלט קריא למכונה (JSON אחד), יציב ומתועד כאן, וקודי היציאה קבועים.

ה-CLI משתמש באותו קוד בדיוק כמו החלון: אותה בדיקת כונן, אותו מנוע סריקה, אותו שחזור (אותן תיקיות ואותו דוח CSV עם SHA-256), אותו רופא קבצים — ואותה חסימה של שחזור לכונן שנסרק.

הבטחות

  • קריאה בלבד מהמקור. ה-CLI לא כותב אף פעם לכונן או לקובץ התמונה שנסרקים. הוא כותב רק ליעדים שנתתם: --to, --save, --list. יעד שנמצא על הכונן שנסרק (או שהוא קובץ התמונה עצמו) נחסם — קוד יציאה 4.
  • מה אין ב-CLI (כי הם כותבים לכוננים): תיקון כונן, החלפת דרייבר («הכונן לא מופיע?»), ניקוי התקנים, בדיקת כרטיס ותמונת כונן. אלה רק מהחלון, אחרי מסך שמראה מה ישתנה.
  • לא נפתח חלון, ואין בקשת הרשאות. כונן לפי אות או דיסק פיזי דורשים הרשאות מנהל. בלעדיהן הפקודה נכשלת עם הקוד needs_admin (יציאה 4) ולא מבקשת UAC בעצמה. קובצי תמונה וסריקות שמורות עובדים בלי הרשאות מנהל.
  • בלי ההגדרות של המשתמש. ה-CLI לא קורא ולא כותב את הגדרות התוכנה. הפלט שלו באנגלית.

איך סוכן AI משתמש בזה

  1. מריצים עם --json. ב-stdout יוצא מסמך JSON אחד בדיוק; ההתקדמות והאזהרות יוצאות ל-stderr.
  2. בודקים את קוד היציאה (הטבלה למטה) ואת ok. כשיש תקלה יש error.code (מילה קבועה) ו-error.message (משפט באנגלית).
  3. סדר מומלץ: drives ← check ← scan --save ← recover --dry-run ← recover --to.

ה-exe הוא תוכנת חלונות (WinExe), ולכן הדרך להריץ אותו משנה:

מאיפה איך הערה
cmd, Git Bash, Python, Node IsraRecover.exe cli scan E: --json > out.json מחכה לסיום, קוד היציאה נכון
PowerShell & $exe cli scan E: --json | Out-String | ConvertFrom-Json בלי צינור (|) PowerShell לא מחכה ולא קולט פלט
PowerShell, שמות בעברית [Console]::OutputEncoding = [Text.Encoding]::UTF8 לפני ההרצה PowerShell 5.1 מפענח לפי דף הקוד של הקונסולה
כל מעטפת cmd /c "IsraRecover.exe cli drives --json > out.json" תמיד מחכה ומחזיר את קוד היציאה
חלון cmd אינטראקטיבי cmd /c IsraRecover.exe cli drives בלי cmd /c שורת הפקודה חוזרת לפני שהפלט מגיע

הפלט ל-stdout ול-stderr הוא UTF-8 בלי BOM כשהוא מנותב לקובץ או לצינור, ויוניקוד ישיר כשהוא מוצג בקונסולה. Ctrl+C עוצר את הסריקה או השחזור בצורה מסודרת: התשובה עדיין נכתבת, cancelled: true, וקוד היציאה 5.

קודי יציאה

קוד שם מתי
0 ok הסתיים בלי בעיות
1 usage פקודה או אפשרות לא מוכרות, ערך חסר או לא תקין
2 not_found המקור (כונן, דיסק, תמונה, סריקה שמורה, קובץ) לא קיים או לא נפתח
3 nothing הפקודה רצה ולא נמצא כלום (אין קבצים, או ששום קובץ לא עונה לסינון)
4 refused סירוב: יעד על הכונן שנסרק, חסרות הרשאות מנהל, או שצריך קודם לעשות תמונת כונן
5 partial הסתיים עם חלק מהשגיאות: קבצים שנכשלו, עצירה ב-Ctrl+C, או שהכונן התנתק

קודי שגיאה (error.code): usage, bad_source, source_not_found, open_failed, needs_admin, destination_on_source, low_space, destination_failed, image_first, lab, bitlocker, cancelled, failed (תקלה לא צפויה — ההודעה כוללת את סוג החריגה).

מבנה התשובה

כל תשובה היא אובייקט אחד. מפתחות קבועים, camelCase. מפתחות חדשים יכולים להתווסף; שינוי שם או הסרה של מפתח יעלו את formatVersion (שמופיע ב-cli version).

{ "ok": true, "command": "scan", "exitCode": 0, "...": "השדות של הפקודה", "warnings": [] }
{ "ok": false, "command": "scan", "exitCode": 2, "error": { "code": "source_not_found", "message": "No such file: D:\\x.img" }, "warnings": [] }

ok הוא false רק כשיש error. בקוד 3 ו-5 התשובה הרגילה מגיעה עם ok: true — קוד היציאה אומר את השאר.

מקור (<source>): אות כונן (E: — המחיצה הזאת בלבד), דיסק פיזי (disk:2 או \\.\PhysicalDrive2 — כל הדיסק), קובץ תמונה (IMG, VHD, VHDX, VMDK, E01 וכל מה שהמנוע פותח), או סריקה שמורה .rscan (רק ב-recover).

הפקודות

cli version · cli help [command]

גרסת התוכנה וגרסת פורמט ה-JSON; רשימת הפקודות, האפשרויות, קודי היציאה וההבטחות (גם ב---json).

cli drives

מה שמסך הבית מראה: כל דיסק פיזי, הסוג (sd, stick, external, ssd, virtual, hdd), החיבור, הגודל, בריאות SMART (good, warning, bad, notAvailable — בלי הרשאות מנהל לרוב לא זמין), והמצב במילה אחת כמו בשורת הכונן (system, smartBad, smartWarning, noLetter, raw, ok). לכל מחיצה: אות, מערכת קבצים, גודל ומקום פנוי. קריאה בלבד, בלי הרשאות מנהל.

cli check <source> [--situation deleted|formatted|noisy|unsure]

«בדיקת הכונן» — אותם ארבעה שלבים (open, health, structure, history), כל אחד עם state (ok, warn, bad, skipped) ומשפט, ואחריהם ההחלטה: action (quick, deep, fixed, image, lab, bitlocker), הסיבה, mode של הסריקה המתוכננת והמלצה במשפט. --situation הוא התשובה ל«מה קרה?» ומשנה את ההחלטה כמו במסך. fixed = סקטור אתחול פגום עם גיבוי תקין: הסריקה תקרא את הכונן דרך הגיבוי (בזיכרון, בלי לכתוב).

cli scan <source> [--mode auto|quick|deep|signatures] [--save x.rscan] [--list x.json|x.csv]

הסריקה של התוכנה. auto (ברירת המחדל) מריץ קודם את הבדיקה ועושה מה שהיא החליטה; כונן חלש (image_first), תקלת חומרה (lab) או BitLocker נעול (bitlocker) נחסמים ביציאה 4 — עם --mode quick|deep סורקים בכל זאת. quick = מערכות הקבצים בלבד; deep = כל הכונן: מערכות קבצים, חתימות ומחיצות שאבדו; signatures = «לפי סוג קובץ» עם כל הסוגים (כרגע זהה ל-deep, כמו בחלון).

הסטטוס של כל קובץ הוא המילה של מסך התוצאות: intact (תקין), partial (חלקי), overwritten (נדרס), notChecked (לא נבדק). deleted = כל קובץ שכבר לא קיים בכונן (נמחק, אבד, או נמצא לפי חתימה). --save כותב סריקה שמורה שהחלון פותח ו-recover מקבל. --list כותב את כל הקבצים (CSV עם BOM, או JSON).

שורת קובץ (ב---list, ב-recover --dry-run): id, path (תיקייה\שם כמו בחלון; הקטע הראשון הוא המחיצה או «Found by content»), folder, name, size, type (סיומת), category, status, state (existing/deleted/lost/carved), deleted, startOffset (הבית הראשון במקור; ‎-1 כשהנתונים בתוך הרשומה עצמה או לא ידועים), modified, created, deletedTime (ISO 8601, שעון מקומי, או null), confidence (0–100), origin, nameOnly.

cli recover <source|x.rscan> --to <folder> [--include glob] [--type jpg,docx] [--status ...] [--deleted-only] [--dry-run]

השחזור של התוכנה: אותן תיקיות, קבצים חלקיים בתיקייה נפרדת, «דוח שחזור» ו-CSV עם SHA-256 לכל קובץ (csvPath). מקור (כונן או תמונה) נסרק קודם (--mode, ברירת מחדל auto); סריקה שמורה .rscan נלקחת כמו שהיא, והמקור שלה נפתח מחדש (אותה תמונה, או דיסק עם אותו דגם וגודל). אם המקור חסר — --dry-run עדיין מציג את הרשימה, שחזור לא.

  • --to על הכונן שנסרק, או קובץ התמונה עצמו → סירוב, יציאה 4 (destination_on_source), אותה בדיקה כמו בחלון. אין מספיק מקום → יציאה 4 (low_space).
  • --include: * ו-?. עם \ או / מושווה לנתיב (גם בלי שם המחיצה; ** חוצה תיקיות), אחרת לשם. אפשר כמה פעמים.
  • --type: סיומות מופרדות בפסיק. --status: intact, partial, overwritten, not-checked או any (ברירת מחדל).
  • --deleted-only: רק מה שכבר לא בכונן. קובץ שידוע רק בשמו (nameOnly) לא משוחזר אף פעם.
  • --dry-run: רשימת הקבצים (files, שורות קובץ), בלי לכתוב כלום. --to לא חובה, ואם ניתן — נבדק.
  • יציאה 0 רק אם הכול נכתב; קובץ שנכשל, קובץ שכולו אפסים (הנתונים נמחקו — לא נשמר), עצירה או ניתוק → 5.

cli doctor <file...> [--repair --to <folder>]

רופא הקבצים: לכל קובץ verdict (healthy, truncated, broken, overwritten, codec, container, unknown), משפט, הסיבה והפרטים, ו-canRepair. עם --repair הקבצים שאפשר לתקן נבנים מחדש לתוך --to (repaired, partial, notRepaired לכל קובץ, ו-outputFiles). הקבצים המקוריים רק נקראים — עותק מתוקן הוא תמיד קובץ חדש (שם תפוס מקבל « (2)»). אין מה לתקן → 3; קובץ שלא נקרא או תיקון שנכשל → 5.

הרשאות מנהל

  • כונן לפי אות (E:) ודיסק פיזי (disk:N) נקראים רק כמנהל — Windows לא נותן לקרוא דיסק אחרת. פותחים «שורת הפקודה (מנהל)» או PowerShell כמנהל ומריצים משם. ה-CLI לא מבקש הרשאות בעצמו.
  • drives עובד גם בלי; רק SMART לרוב לא זמין.
  • סריקה שמורה של כונן צריכה הרשאות מנהל כדי לפתוח שוב את הכונן (בלעדיהן: --dry-run מציג את הרשימה עם אזהרה).

For AI tools (English summary)

IsraRecover.exe cli <command> [options] --json prints exactly one JSON object to stdout; progress and warnings go to stderr. Commands: version, help [command], drives, check <source>, scan <source> [--mode auto|quick|deep|signatures] [--save f.rscan] [--list f.csv|f.json], recover <source|f.rscan> --to <dir> [--include glob] [--type ext,...] [--status intact|partial|overwritten|not-checked|any] [--deleted-only] [--dry-run], doctor <file...> [--repair --to <dir>]. A source is E:, disk:N, or an image file (IMG/VHD/VHDX/VMDK/E01).

Exit codes: 0 ok · 1 usage · 2 source not found / cannot open · 3 nothing found · 4 refused (destination on the scanned drive, needs_admin, image_first, lab, bitlocker, low_space) · 5 finished with errors (failed files, Ctrl+C, disconnect). Failure: {"ok": false, "exitCode": N, "error": {"code": "...", "message": "..."}}.

Read-only guarantee: nothing is ever written to the source; only --to, --save, --list are written, and a target on the scanned drive is refused. Drive repair, driver switch, device cleanup, card test and imaging are not in the CLI. Drive letters and disks need an elevated prompt; the CLI never self-elevates. The exe is a GUI-subsystem program: from PowerShell pipe it (& IsraRecover.exe cli drives --json | Out-String | ConvertFrom-Json, after [Console]::OutputEncoding = [Text.Encoding]::UTF8), or run it through cmd /c "... > out.json"; cmd, bash and subprocess APIs that redirect stdout wait for it and get the exit code.
